# Shared core integration boundary

Nest imports the shared DurableWorkStore from the pinned Orbit package. Schedule cursors, occurrence materialization, stable request IDs, attempts, cancellation, approval state and one visible result belong to that store. Nest's host supplies deterministic selected-source reads and explicit loopback-only Ollama inference or optional local Apple text chat. It does not provide arbitrary agent model tools. Project-bound Ollama chat can use Core's fixed, host-permitted memory search through an ordinary managed run; see the [Project integration guide](project-session-integration.md).

The existing professional orbit-app checkout and its Docker worker boundary are preserved. Its current schedule implementation consumes a reservation before random-ID submission. A future separate migration must bind one persisted occurrence to a stable Orbit request ID, preserve that ID through worker transport retries, and map terminal worker events to durable completion. Submission acceptance is not completion. Worker operation journals, persisted approvals and explicit external reconciliation must remain authoritative for opaque tool effects; an interrupted worker must never be treated as a safely repeatable read-only Nest summary.

Legacy schedules need an explicit one-time import record and reversible compatibility mapping. UI schedules can be a projection of the shared store, but must not independently advance their cursor. Existing Docker ownership/recovery and approval regression tests must pass in that separate branch. No partial migration is enabled implicitly in this prototype.

The vendored core archive contains existing Orbit licensing and notices unchanged. It is a reviewed local package snapshot of the core implementation now merged in Orbit main, not a publication. Source commit and SHA-256 are in vendor/core-provenance.json; npm's lockfile also records package integrity. Verify with npm run core:verify before installation. Upgrading requires rebuilding and reviewing that exact core revision and updating both provenance and lockfile.

Use immutable source-named archives when upgrading. npm can retain an older installed package if the same local archive path/version is overwritten. core:verify checks archive SHA-256 and lockfile SHA-512; core:verify-installed additionally checks the installed scheduler, Apple adapter and Swift source against the exact source build.

Nest pins Orbit main d7535aa86920d3835f6d9ab3f4afbe75174d2f96 (merged PR #43). The official GitHub source archive was built and tested independently without using or modifying an existing Core checkout. Core headers/build, 1,483 synthetic tests and the independent package consumer passed before npm pack; no package was published. The source/archive digests and runtime-module digests are recorded in provenance. Ollama SDK 0.6.3 matches the inspected Core lockfile. The host calls atomic claimNext rather than choosing and claiming a queued record in separate operations. Core owns priority, durable aging, same-key ordering and the running/unknown stop; Nest still executes one job at a time. Existing callers without priority keep the normal default. This package update does not assign new priorities to UI input or change payload values into execution configuration. No shared-core edits or publication are made by this update.

The new core reads legacy v1 work state and preserves its IDs and application data. After new state is saved, the old core package cannot read that format. Do not downgrade an existing userData directory to the old Nest build. Unknown opaque work stays stopped until explicit reconciliation. The installed verification checks scheduler, event-store, event-inbox, priority and local Apple implementation hashes in addition to archive and lock integrity.

The desktop bundler resolves four broad Apple adapter/helper export barrels to their exact named implementation modules (operator, message, errors and tool-result definition). The vendored source is unchanged; this preserves the shared adapter while avoiding eager, unused tool/cloud registries. For the pinned Agent, the desktop build also checks the built-in catalog hash, retains Core registry/metadata validation, and replaces only generic handler construction with a fail-closed error. Ambient workspace-settings discovery is disabled for the Agent; Core's explicit settings merge/validation is retained. The default model factory is unavailable; every managed run must inject its saved local model. Core memory-search definitions, handlers and capability policy are not replaced. Host configuration explicitly clears inherited tool includes. Runtime bundles are checked for unrelated glob and cloud SDK code. `npm run test:packaged-memory` verifies this compiled boundary with Electron in Node mode, without a window or real inference. Optional Swift compilation is explicit and records source/target/binary provenance; the binary is packaged as a resource, not executed from an ASAR or temporary checkout.

## Project/Session host bridge

Nest opens the core SQLite Project adapter and registered Session repository in an app-owned context subdirectory. A narrow ProjectService/ProjectMemoryService bridge supplies explicit membership and bounded context; it never enables default Agent tools, inherited MCP servers, extraction or provider fallback. Project chat constructs an explicitly configured Agent with the saved local model and only a revocable search permission; Apple keeps its text-only route. [Decision 0009](decisions/0009-project-session-context.md) records ownership and recovery choices; the [integration guide](project-session-integration.md) is the maintained workflow and qualification contract.

The CJS Electron main bundle dynamically loads an ESM context module. Its core SQLite adapter resolves the adjacent ESM Worker by import.meta.url. The complete catalog runtime, its dependency licenses and the Electron-built better-sqlite3 binding are unpacked under app.asar.unpacked, outside the ASAR. Startup checks artifact SHA-256 values and the Electron version, platform and architecture before opening work state. @electron/rebuild is pinned in the lockfile. Node unit tests retain their own installed Node binding; the desktop build does not replace it. The package has been exercised on macOS arm64; portable source builds do not compile an unused Electron native binding. Packaging targets the macOS build host's architecture. Other native targets require qualification.

Creation intents are saved before core mutations and replay the same operation IDs. Legacy/Apple completed work is saved in DurableWorkStore before Session projection; deterministic message IDs and content/correlation checks make that local projection retryable. Managed Ollama turns are already stored by Core and are correlated without duplicate projection. This is a recovery protocol across stores, not one transaction across EventStore, SQLite and transcript files. A completed result is not inferred from transcript or notification delivery. Known-dead Session ownership follows core recovery; retained guards, unknown owners, corruption or conflicting results remain blocked for inspection. Opaque operations are never replayed to repair a transcript.
