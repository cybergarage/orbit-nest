# One week of self-use — proposed, not scheduled

This is a manual validation protocol, not scheduled monitoring or a completed study. Use synthetic writing/code tasks and paper or local notes outside Git; publish only aggregate observations. Begin with the static concepts, then simulate actions without changing runtime features.

| Day | Exercise | Observation |
| --- | --- | --- |
| 1 | Find a small manuscript step from Home | Time to identify and start; unnecessary settings visits |
| 2 | Start a development task | Whether the same language fits; edits to the proposed step |
| 3 | Interrupt after a few minutes | Ability to find and understand the return note |
| 4 | Simulate Quit, sleep and a late routine | Explain elapsed timer versus actual execution |
| 5 | Simulate model failure and cancellation | Find retry, distinguish stop requested from cancelled |
| 6 | Review, edit and remove a memory proposal | Explain what is stored and what is merely suggested |
| 7 | Repeat without guidance; review observations | Desire to reuse; unresolved confusion; revise hypothesis |

Provisional observable criteria: start a bounded task within 60 seconds on at least five of seven exercises; resume the saved next action within 30 seconds on at least four of five return trials; correctly explain all three cases (window closed / Quit / paused routine); no false claim that timer expiration or model text proves manuscript completion; locate memory edit/remove and unknown-outcome recovery without coaching. Record denominator, assistance, failed attempts and exact confusion rather than reporting a general success score.

Also record whether the character feels welcome or distracting, whether reminders are disabled, and whether someone prefers a character-free mode. One person's week is directional evidence only. If start or recovery is still confusing, revise the flow before selecting implementation scope. Review persona and ADR 0002 explicitly after the week; neither merge nor a passed exercise accepts it automatically.
